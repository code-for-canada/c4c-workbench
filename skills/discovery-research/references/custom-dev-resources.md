# Custom Development Resources

What existing open source software OR open standards would make this solution better?

## Open-source repositories

What existing open-source repositories or frameworks might be useful to develop the solution? Look for:

- Active maintenance (recent commits, healthy issue triage, real contributors).
- Compatible licensing for the partner's use case.
- Community traction and production deployments.
- Alignment with the actual user stories — not just the surface-level problem area.

## Digital public goods and digital public infrastructure

Only where relevant, search authoritative registries for vetted DPGs and DPI:

- [Digital Public Goods Registry](https://www.digitalpublicgoods.net/registry).
- [Digital Public Infrastructure Map](https://dpimap.org/).

DPGs and DPI are relevant when the partner's work is relevant to a UN sustainable development focus area or building service infrastructure that other governments could share, and they want to align with international precedent.

## Open and de-facto technical standards

What standards are relevant to making the solution interoperable and standards-based?

- **De-facto API standards** — patterns the industry has converged on (e.g. S3-compatible object storage APIs, OAuth/OIDC for auth, OpenAPI for HTTP API descriptions, FHIR for health data, etc).
- **Open data standards** — relevant whenever there is data that should be portable, comparable across jurisdictions, or consumable by the public. Match to the data type (e.g. transit, civic addresses, public spending, identity, building permits).


## Output

A short list for each category. Each item:

- Bold name, hyperlinked to authoritative source.
- One sentence on why it is relevant.
